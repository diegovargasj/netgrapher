## 1. What netgrapher is (30-second version)

A Python tool that builds a **best-effort network-layer (L3) topology graph** — subnets, routers,
hosts, the Internet — from observed traffic, optionally supplemented by probes it sends. It has
three discovery modes (`passive`, `active`, `reactive`), works from live capture or pcap files,
and ships an interactive local web UI to view/edit/annotate/export the graph. Output is a
versioned `.ngraph` project file. Every node/edge records its **evidence** and a **confidence**.

L1/L2 topology (switches, cables, VLANs) is explicitly **out of scope** — L2 headers are used
only as *evidence* for L3 conclusions. Read design doc §1.3 for non-goals.

## 3. CRITICAL operating rules (read before running anything)

These are hard constraints. Violating them can leak private data or scan networks without
authorization.

1. **Tests MUST NEVER touch the real network or the real host.** This is enforced by an autouse
   fixture in `tests/conftest.py` that:
   - points `NETGRAPHER_DUMPCAP` at a non-existent path,
   - replaces `read_host_config` in every module that imports it with a function that raises,
   - patches `SocketTransport.__init__` to raise.
   When you add a module that reads host config or sends probes, **extend that fixture** so the
   guard still covers it. Tests use `tests/fake_transport.FakeTransport` and the fake dumpcap
   wrapper (`tests/fake_dumpcap.py`) instead.

2. **Never run `active` or `reactive` mode against a network you are not authorized to scan.**
   They send packets. For any manual check use `--dry-run` (prints the plan, sends nothing).

3. **Never open or analyze the owner's personal capture files.** There are pcaps elsewhere on the
   development machine (unrelated personal/Wi-Fi captures). Only analyze capture files the owner
   explicitly hands you, or the synthetic captures generated by `tests/synthetic.py`.

4. **Live capture and real probing are unverified against a real network in code review.** The
   socket-based `SocketTransport` (ICMP ping socket, UDP+`IP_RECVERR` traceroute) and live dumpcap
   capture have only been exercised with fakes and a couple of short manual passive runs. Treat
   real-network behavior as *untested* until someone validates it (see §9, §10).

5. **The engine must never require root.** Capture privileges live in `dumpcap` (file
   capabilities); v1 probes use only unprivileged sockets. Keep it that way.

6. **The UI binds to 127.0.0.1 only**, requires a session token, validates Host/Origin, and sends
   a strict CSP. Don't loosen these. Captured names/IPs are rendered as **text only**, never HTML.

## 4. Setup, build, test, run

No `uv.lock` is committed yet (uv was not available on the dev machine; see §9 TODO). Use a plain
venv:

```bash
cd netgrapher
python3 -m venv .venv
.venv/bin/pip install -e .                    # runtime deps
.venv/bin/pip install pytest hypothesis httpx playwright mypy ruff   # dev deps

# Quality gates (all must pass before committing):
.venv/bin/pytest -q
.venv/bin/mypy
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

**UI/browser tests** use the system Chromium (`chromium` on PATH or `NETGRAPHER_CHROMIUM=/path`).
They are skipped if neither is found — so a green `pytest` on a headless CI without Chromium does
**not** mean the UI is covered. Run them where Chromium exists.

**Running the tool** (see `netgrapher --help` and design doc §12 for all flags):

```bash
.venv/bin/netgrapher doctor                                  # check capture permissions
.venv/bin/netgrapher discover --read capture.pcapng -o net.ngraph   # offline analysis
.venv/bin/netgrapher discover --duration 10m --ui -o net.ngraph     # live passive + UI
.venv/bin/netgrapher discover --mode active --cidr 10.0.0.0/24 --dry-run   # preview probes
.venv/bin/netgrapher ui net.ngraph                           # open a saved project
.venv/bin/netgrapher info net.ngraph                         # summary + coverage report
.venv/bin/netgrapher export net.ngraph --format dot -o net.dot
```

To exercise the pipeline without any capture, generate the synthetic "office" pcap:
```python
from tests import synthetic; synthetic.write_pcap(Path("office.pcap"), synthetic.office_frames())
```

## 6. Data flow (how a run works)

```
capture (dumpcap pipe | pcap file)
  -> CaptureReader (RawPacket) -> decode() (DecodedPacket) -> extractors (Observations)
  -> FactStore  ── every ~2s ──> infer() -> Graph (entities+links+evidence, each with confidence)
                                     │
   (active/reactive only)           ├─ live UI: diff vs previous graph -> WebSocket event
   planner <- new entities ─────────┘
      │ submit Target (scope/dedup/generation/budget gate)
      ▼
   Prober (own thread, asyncio, rate-limited) -> SocketTransport -> probe replies
      │ Observations (provenance=probe)
      ▼
   back onto the run-loop queue as FactBatch -> FactStore  (single-writer invariant preserved)
  -> final infer() -> Project (graph + runs + flows + annotations + view) -> .ngraph
```

Key invariant: **the FactStore has a single writer** (the main run-loop thread). The prober never
writes it directly; it emits facts through a callback that enqueues them for the main loop.

## 7. Deviations from the design doc (intentional — don't "fix" these)

1. **Probe replies are read on the probe's own socket**, not correlated out of the capture stream
   (design §5.4 imagined capture correlation). Reason: v1 unprivileged mechanisms (ping socket,
   TCP connect, `IP_RECVERR`) hand you the reply directly; simpler and more reliable. Consequence:
   `discovery/registry.py` is an unused stub.
2. **Mercator / IP-ID router-alias probing is deferred to v2.** PTR lookups are implemented.
3. **UI hierarchical layout uses `dagre`, not `elkjs`** (EPL-2.0), and SVG export uses an in-house
   serializer in `web/js/svg.js`, because `cytoscape-svg` is GPL-3.0 (incompatible with MIT).
4. **Own pcap/pcapng reader** (`capture/source.py`) instead of dpkt's (dpkt's can't do pipes,
   multi-interface, or ISB drop stats).
5. **Scope semantics:** an address is in scope iff it's in the allow list and not denied;
   `allow_public` additionally permits *any* public address (reactive opt-in only). Active mode's
   allow list is exactly the user CIDRs, so it never probes outside them even for public CIDRs.

All five are recorded in the design doc too; keep both in sync if they change.

## 8. Known bugs, rough edges & risks

Ordered roughly by importance. None are currently failing tests — these are gaps, unverified
paths, and latent issues.

- **Real-network probing is unverified.** `SocketTransport.udp_trace` parses
  `sock_extended_err`/`IP_RECVERR` by hand (`transport.py::_parse_sock_extended_err`); it has
  never been run against real ICMP time-exceeded traffic in this codebase's tests. ICMP ping
  sockets depend on `net.ipv4.ping_group_range`. **Validate end-to-end on a lab network before
  trusting active/reactive output.**
- **Live capture is barely exercised on real traffic.** Two short manual passive runs only. No
  soak test, no high-rate drop test (NFR-2 unvalidated).
- **Inference recomputes the whole graph every 2s** (`discover.py` tick). On long/busy captures
  this is O(facts) each tick and can fall behind, filling the queue and causing dumpcap drops.
  Incremental inference is a real TODO (design §5.3).
- **Rule weights are guesses** (`infer/weights.py`). They were never calibrated against ground
  truth because `tests/labs/` is empty. Expect precision/recall to need tuning.
- **Reactive `/22` sweeps are large** (up to ~1022 ICMP probes) and can exhaust the default budget
  quickly; fine functionally but worth smarter prioritization.
- **`registry.py` is a dead stub** — either delete it or repurpose it if you ever add capture-based
  reply correlation. Don't import it expecting behavior.
- **Flow overlay is recorded but never displayed** in the UI (`flows.py` data sits in the project
  unused by `web/`).
- **IPv6 is skipped entirely in inference.** The data model is nominally dual-stack and IPv6
  host-config/addresses are deliberately filtered out of the IPv4 rules (so they can't create
  bogus entities — this bug was already fixed once; keep the `is_ipv4` guards in `infer/context.py`
  and `capture/hostinfo/__init__.py`).
- **No `uv.lock`.** Dependency versions are only lower-bounded in `pyproject.toml`.
- **Playwright UI tests are skipped without Chromium** — a green CI can hide UI regressions.
- **Default numeric knobs** (rates, budget, timeouts, convergence window) are first guesses;
  design doc §18 says recalibrate after lab runs.

## 10. Settled decisions (do NOT relitigate without the owner)

From the design process (design doc §19 has the full log):
- **L3 only.** L2 used solely as evidence.
- **Live capture is the primary input;** pcap/pcapng is a secondary input through the same pipeline.
- **Three modes:** passive / active / reactive, mutually exclusive per run. **Active probes only
  the user's `--cidr`s and never reacts to observed traffic.** Reactive probes only observed
  targets within scope.
- **Dual-stack model, IPv4 first.** **Linux first**, OS code behind interfaces.
- **One-shot runs** (duration/packets/converged/Ctrl-C); long-running monitor is later.
- **MIT license, no GPL runtime deps** (hence no scapy; dpkt for parsing). Snaplen default 512.
- **v1 probes are unprivileged**; privileged helper is v2.
- **UI = localhost FastAPI + Cytoscape.js**, discovery driven from the CLI in v1.
- **Project format:** versioned gzipped JSON (`.ngraph`); annotations stored separately with
  stable ids.

## 12. How to extend common things (quick recipes)

- **New protocol extractor:** add `extract/<proto>.py` with `extract(pkt) -> Iterator[Observation]`,
  register it in `extract/__init__.py::EXTRACTORS`, add a `FactKind` if needed, and unit-test it in
  `tests/unit/test_extract.py` using `tests/synthetic.py` builders.
- **New inference rule:** add a weight to `infer/weights.py`, emit evidence via
  `ctx.evidence(rule, key, facts, summary)` in the relevant `infer/rules/*.py`, and test via
  `graph_from_frames`/`graph_from_observations` helpers in `tests/unit/test_inference.py`. If you
  change inference output, **regenerate the golden file**:
  `NETGRAPHER_UPDATE_GOLDEN=1 pytest tests/golden` and review the diff.
- **New probe type:** add a `ProbeKind`, a branch in `probes/run_probe`, a `ProbeTransport` method
  (+ `FakeTransport`), and planner logic. Keep it unprivileged or put it behind the (future) helper.
- **New API endpoint / UI feature:** add to `server/api.py`, respect the auth middleware, and add a
  Playwright assertion in `tests/ui/`. Never insert captured text as HTML.
- **New project-format field:** bump `FORMAT_VERSION` in `project/format.py` only if you break
  compatibility; add a migration in `project/migrate.py`; update `tests/unit/test_project.py`.
